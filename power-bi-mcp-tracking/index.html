Tracking Claude Code in Power BI

An eight-minute narrated explainer on service principals, the Power BI MCP servers and the Get Activity Events admin API · November 2026

Interactive version (animation in the browser) Download MP4 (21 MB) Power BI MCP docs

What it covers

  1. Two jobs for a service principal. The actor, which is Claude Code's identity, and the auditor, which is a script that reads the activity log. They need different permissions.
  2. Hosted Authoring MCP server. It signs in as the person and logs ReadByPowerBIMCP and ModifiedByPowerBIMCP under their name. It has no service principal option.
  3. Local server with a service principal. Set --authmode=serviceprincipal and the Azure identity variables, and grant workspace Member or Admin access and XMLA read-write. Row-level security is not enforced.
  4. What gets logged. The local server doesn't log MCP events. It leaves three other trails: XMLA activities such as ConnectFromExternalApplication, workspace monitoring under MCP-PBIModeling, and local audit files.
  5. The auditor. Turn on "Service principals can access read-only admin APIs" for a security group. Don't give the app admin-consent Power BI permissions, and don't give it Tenant.Read.All.
  6. Get Activity Events. Each call covers one UTC day, and the log goes back 28 days. You can filter on Activity and UserId, and you get up to 200 requests an hour. Load it into a lakehouse every day, and run one test call to learn the service principal's UserId.
